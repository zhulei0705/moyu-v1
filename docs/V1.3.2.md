# V1.3.2 本地服务托管与安全恢复

仅操作自建模拟器。生产数据库不替换；007迁移只新增服务实例、服务事件、Agent状态历史、恢复审计四张表。迁移前一致性备份保存在reports/v132-baseline，提供007_reliability_down.sql，回退前必须停止服务并另做完整备份。研究服务异常恢复的未知任务改为INTERRUPTED；确定的Worker异常仍为FAILED，主动停止为STOPPED。

## 日常命令

在项目目录运行PowerShell：

```powershell
.\start.ps1 -SkipSetup -NoBrowser
.\status.ps1
.\stop.ps1
.\restart.ps1
```

默认127.0.0.1:8000，默认不启用Watchdog，不安装系统服务或计划任务。第一次需要安装依赖和构建时不加-SkipSetup。start只有服务身份与健康检查通过后才打开浏览器。

如需减少对启动工具/终端进程树的依赖，可显式使用 `start.ps1 -SkipSetup -NoBrowser -IndependentHost`。它通过Windows已有的本地WMI进程创建接口启动同权限后台管理器，不安装新服务，不更改权限，不启用Watchdog。接口拒绝时直接报错，不尝试提权或绕过。重启时也需保留 `-IndependentHost`。现已实测启动命令返回后进程仍运行、可核对实例并正常停止；这不等于承诺抵抗任何外部终止。

明确启用自动拉起：

```powershell
.\start.ps1 -SkipSetup -NoBrowser -Watchdog -MaxRestarts 3 -BaseDelay 2 -StartupTimeout 30
```

重启后如需继续Watchdog，应显式执行 `restart.ps1 -Watchdog`。可配置-Port和-Database用于隔离测试；不要把测试库路径用于生产。运行中的原uvicorn服务不能被脚本接管或自动终止，需先核实身份并停止。

## 监控规则

后台管理进程持有Windows文件锁，控制命令有独立锁，同一数据库路径还有共享锁，阻止同端口或不同端口的重复服务。实际Python PID与健康接口instance_id共同核对，兼容Windows虚拟环境启动器和实际子进程PID不同。只有由自己Popen创建的子进程归其管理。

Watchdog仅对已退出的子进程自动拉起；默认最多3次，退避2、4、8秒，延时上限30秒。每次显式start建立新的管理周期。本次周期restart_count和历史total_restart_count分开记录。退出码和检测时间持久化，真实原因不知道时仍为UNKNOWN。拒绝未知端口占用，权限或审批失败不会绕过。

stop先保存带manager_id的主动停止标志，服务的异步停止观察器请求Uvicorn优雅退出；Worker通过原停止屏障释放资源，SSE连接释放，SQLite连接关闭。正常停止、退避等待期间停止、启动超时取消均不会自动拉起。只有用户再次显式start可清除旧停止标志。优雅停止超时不会强杀未知进程，保留停止意图并返回错误。

启动等待默认30秒；初始化超时会写停止标志，管理器停止等待，不无限重试。Windows原子替换遇到读共享冲突时短暂重试20次、约1.7秒上限；不会通过删掉旧状态文件或修改权限绕过失败。持续失败仍报错并请求停止自己的服务。

## 数据与任务恢复

每轮UUID run_id沿用原架构；所有状态变化写agent_state_history，暂停、恢复、停止请求另外记录控制原因。服务启动先核对RUNNING遗留任务，标记INTERRUPTED并写agent_recovery，策略STOP_UNCONFIRMED_NO_REPLAY。不会重发未知攻击/拾取，不自动重建旧世界，也不自行开始新任务。

原副本成功结算新增幂等保护，COMPLETED不会再次写奖励或结算日志；中断任务禁止按成功结算。九星结算沿用原事务及唯一键，未知结果只统计已持久化事件且成功=false。INTERRUPTED单独展示，不混为确定战斗失败。历史已完成记录不修改。

## 真实Web状态

所有旧页面右下角“服务”面板可展开，显示服务/Worker状态、启动、每秒持久化心跳、异常退出检测时间、Watchdog和重启计数、Agent恢复、SSE与线程数量。未托管服务的重启次数无依据时为null，不填0。服务断线时明确为待确认，保留最后已知数据。

GET /api/service/status；GET /api/agent/state-history?run_id=...；/api/health新增instance_id和pid。上次真实退出时刻无法确认时返回null，检测时间不是内核退出时间。心跳数据库暂时写入失败会记录堆栈并按间隔重试，服务显示DEGRADED，成功后恢复。

## 日志与资源

.runtime/service-8000/state.json记录托管状态；events.jsonl记录管理事件；service.log记录请求、Python异常、启动与优雅退出，5MiB轮转，保留5份；server.log捕获进程启动阶段及原生stderr，manager.log捕获管理器异常。业务SQLite日志完整保留。SSE生成器finally释放连接计数，托管Uvicorn并发连接上限128。业务日志、图像证据和诊断事件长期增长，当前不自动删数据，需规划磁盘容量。

## 范围与限制

原start.ps1前台Uvicorn确实依赖终端/会话生命周期；此前退出的具体原因仍未确定。压力测试新发现并修复Windows状态文件读共享导致os.replace拒绝访问，不能把它追认作V1.3.1以前的原因。

Supervisor自身若被外部工具、Windows注销/关机或整组进程终止，无法自我复活。没有安装系统服务，不保证注销或OS重启后自动运行。只重启已退出进程；活着但永久卡住的进程不会被自动强杀，需人工核对。当前实测连续八轮约100秒，不能宣称通过24小时无人值守测试。

请用stop.ps1声明主动停止。直接在任务管理器结束服务进程与异常退出无法可靠区分，在Watchdog已启用时会按异常退出处理。

状态文件残留RUNNING但两个进程已不存在、端口未监听时，status会显示EXITED_UNCONFIRMED并保留recorded_state，不把过期记录冒充运行。2026-10-10再次检测到此类退出，无正常退出日志，原因仍未知；新启动时会写入异常检测审计。
