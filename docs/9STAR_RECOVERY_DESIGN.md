# 九星任务恢复与稳定性设计

执行环境只有自建模拟器。所有数值和资源是模拟假设，历史官方名称只作标签。复用现有 Runtime → ResearchController → ResearchAgent → Vision/A* → World → ResearchRepository 链路和 Vue 监控。

## 执行与证据

观察只读取实际 PNG 像素。角色标记、HUD重复编码、背包容量、目标生命须通过完整性校验；校验分数1表示固定模拟规则下通过校验，不能解释为真实游戏识别概率。低于0.9或未知前置观察不执行动作，最多重新观察3次。动作后视觉失败不重放已执行动作，终止并保留决策前后证据。

每一步从新观察重新选目标并运行A*，只移动到计划下一格。目标消失不视为击杀；动态路径阻塞重观察/规划，持续失败首次加3次重试后停止。攻击要求同目标视觉生命下降或死亡目标/掉落/事件证据，拾取核对金币、碎片、材料的每项视觉增量与实际事件。阶段推进前必须无敌人和掉落；阶段不得倒退或跨越，退出必须已有完成标志且资源守恒。

## 时间与次数边界

| 执行状态 | 活动预算（秒） |
|---|---:|
| PREPARE / QUALIFY / ENTER | 10 |
| SEARCH | 15 |
| NAVIGATE | 60 |
| COMBAT | 30 |
| LOOT | 15 |
| VERIFY / SETTLEMENT | 10 |
| RECOVER | 15 |

Runtime在状态转换前检查上一状态活动预算，研究决策状态还独立计时，阶段及全轮另有独立上界，不能靠状态往返取消全局保护。初始化、结算是同步有界操作，并受全程和底层SQLite等待限制；状态预算不抢占正在执行的Python或native调用。全轮活动180秒，阶段60秒，20秒无确认进度停止；动作适配器2秒，单步观察/证据链路10秒，最多1000步。动作耗时不包含数据库记录和PNG持久化。暂停时间从活动预算扣除，跨轮重置时间基准。每次启动最多100轮；遇到不可恢复异常停止整个连续任务，不继续下一轮。

## 恢复矩阵

| 故障 | 恢复或终止 |
|---|---|
| 一次目标消失 | 新帧重选，未确认击杀 |
| 一次路径阻塞 | 新障碍地图A*重新规划 |
| 持续阻塞 / 永久无路 | 4次验证失败内或NO_PATH立即停止 |
| 一次前置识别失败 | 不动作，有限重采样 |
| 持续识别失败 | 首次加3次重试后FAILED |
| 动作后无法识别 | FAILED，不重复未知动作 |
| 阶段不推进 | 验证重试上限或阶段超时FAILED |
| 角色死亡 | CHARACTER_DEAD，停止，不自动复活 |
| 背包满 | 模拟转存并验证空位、累计资源守恒、实际成本事件 |
| Worker异常 | FAILED；写库失败则人工审核，不再启动 |
| Worker心跳30秒陈旧 | 停止闩锁、人工审核；不强杀未知线程或自动重启存活进程 |
| API短时不可用 | Web查询重连，控制POST不自动重发；状态恢复后人工操作 |
| SSE断线 | Last-Event-ID按持久日志补读，Worker继续，日志去重且最多500行 |
| SQLite写入失败 | 停止动作；独立尝试保存失败状态和结算，不伪造持久成功；持续失败清理内存并拒绝再次启动 |
| 服务进程中断 | 遗留RUNNING转INTERRUPTED，不续跑未知动作；已完成结算不变 |
| 存储容量达2GiB | STORAGE_LIMIT，人工归档后重新启动，不删除历史 |

## 检查点与幂等结算

新增 `agent_checkpoint(run_id,updated_at,status,payload)`。每次动作前写 ACTION_INTENT，payload 包含来源、观察、目标和动作；动作后写 VERIFIED 或 UNCONFIRMED。终止时保存 FAILED/STOPPED。正常结束最后一个 VERIFIED 记录实际退出观察，runs与结算表保存最终完成结果。

检查点只用于审计。进程在动作之后、确认之前中断，即使环境看似已经完成也不重放。恢复沿用 STOP_UNCONFIRMED_NO_REPLAY。下一轮必须新UUID和新模拟世界。

成功结算需四阶段enter/stage/complete事件、场景实际complete/exited/stage=4以及每项库存/成本守恒。在同一SQLite事务中检查全程唯一键、RUNNING资格，写入stage0与四阶段结算和COMPLETED；已存在全程结算不会改写。INTERRUPTED/FAILED/STOPPED不能通过成功结算修改结果。有实际World时失败/停止结算也必须与实际库存/成本一致，否则拒绝不完整结算、进入人工审核。服务中断无法读取原环境时，失败记录resource_basis为PERSISTED_EVENTS_ONLY，明确只描述已保存事件，不声称完整背包，也不计为成功收益。

## 控制、心跳、资源与监控

暂停和恢复使用RLock及Condition动作屏障。停止和紧急停止先置停止闩锁、唤醒Worker，再同步结束；每次启动独立Event，旧请求不会停止新会话，Worker先完成这次停止时接口仍确认成功。在途动作/数据库调用只能待其返回后终止，不允许随后执行新的动作。状态读取等待动作屏障最多50ms，忙碌时返回 action_barrier_busy 和真实停止请求字段。持久化失败可能无法写入STOPPED，但内存停止状态仍可核验；UI标明需要人工审核。

Worker每个循环及退出记录心跳，服务每秒持久心跳并检测陈旧Worker。服务异常重启仍由已有可选Watchdog负责，默认关闭、明确启用才执行、最多有限次数，不把Worker失败当作无限重启请求。

数据库2GiB容量保护在开始及每步检查，保留全部历史；单轮步数和轮次也限制证据增长。业务日志使用索引MAX序号，SSE后台线程分批100条读取，导出固定上界流式分页；Vue日志最多500行、恢复记录最多50条。不会因用户断开页面重启任务。

服务面板显示实际进程运行时间、工作集内存、process_time差值计算的单核CPU百分比、Worker心跳、最后确认动作、当前目标/视觉校验、重试、卡住时间、连续完成数和恢复记录。成功率来自原研究结算报表，异常来自真实持久日志。无法获取的数据显示待获取，无异常样本的自动恢复率为null，不伪造0或100%。

## 可复核短时测试

在项目根目录运行，label必须为未使用的新目录名：

```powershell
.venv/Scripts/python.exe scripts/nine_star_stability_test.py --rounds 10 --tick .08 --label 9star-10-runs-next
.venv/Scripts/python.exe scripts/nine_star_stability_test.py --rounds 100 --tick .005 --label 9star-100-runs-next
.venv/Scripts/python.exe -m pytest -q --basetemp=reports/9star-next-temp --junitxml=reports/9star-next.xml
```

加速仅减小动作间等待，全部动作、视觉和SQLite操作实际执行。每轮保留UUID、事件、PNG、决策、结算；JSON记录轮数、耗时、成功率、异常、CPU、内存、日志和资源守恒。正常测试没有注入故障，自动恢复率无分母时为null；故障测试单独统计。

8小时/24小时需用户给出北京时间开始、结束、可占用时长和跨夜许可，再用隔离库、默认80ms调度、真实墙钟测试。到窗口结束先暂停/停止保存检查点；未达到完整墙钟时长标记未完成，不换算加速轮数为8小时或24小时。超过资源配额或任何不可恢复异常立即停止、保留失败事件；不能为了完成时长而无限重启。

本次100轮证据库约751.23MiB，基线约1.69MiB，约7.50MiB/轮。按10轮默认调度平均14.03秒作容量估算，2GiB默认配额可能在约1小时连续运行后触发；这是容量推算，不是已完成的长时测试。自动证据归档尚未实现，长时窗口前必须先确定保留历史的归档或更大有界容量策略。当前默认配置不能承诺连续8小时或24小时。
