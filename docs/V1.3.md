# 魔域 Web Agent V1.3：九星研究副本自主执行

运行入口：http://127.0.0.1:8000/#/research 。原控制台 http://127.0.0.1:8000/#/console 保留。选择“九星研究副本”，设置轮数、种子，点击启动；后台线程执行完整闭环，浏览器关闭或刷新不推进/停止副本。

## 数据与执行边界

`NineStarResearchDungeon`是独立22×16自建格地图，原20×14 World保持不变。专用构建器从同一份完整官网历史快照读取四阶段、首领名称、已知数量和机制证据，保存到V1.2 twin_scene_revision。优先选择含已知机制的完整快照，避免跨历史版本拼接。OFFICIAL_FACT只用于可追溯名称/描述标签；原知识表继续executable=0、current_verified=0。当前游戏版本未知则NULL。

执行参数单独为SIMULATED_ASSUMPTION：入口/出口、墙体、生成位置、生命120、攻击25、首领生命75、护卫生命50、反击2、阶段清场规则、随机金币40–80、碎片1–3、每敌人物资1、背包容量12、可随地模拟转存及每次1份模拟补给成本。历史第一阶段数量4用于构建测试首领，其余未知数量采用1的显式测试假设；历史名称与模拟色块的对应关系也是模拟赋值，不能当作对官服画面的视觉名称识别。

原始地图、首领属性、掉落率、NPC与技能机关仍未验证；历史机制原文保留为只读证据，不自动转译成已验证的战斗代码。运行适配器仅解析专用预设里的模拟参数，研究事实本身仍RESEARCH_ONLY。任意编辑JSON不能直接执行；通用场景编译器未实现。用户编辑的版本保留，专用构建器需要更新时另存新版本，不覆盖历史。

每轮新建世界并使用seed+轮序，实际生成敌人；击杀导致掉落、拾取修改背包、全阶段敌人和掉落清空后才开放出口，实际走出才能成功结算。四阶段没有靠计时器自动推进。Worker tick仅限速，超时只触发失败。

## 感知、规划与决策证据

复用OpenCV、Agent接口与A*。Agent仅接受NumPy图像，读取模拟配色连通区域和模拟HUD像素，识别人物、首领标记、怪物、障碍、入口、掉落、出口、阶段、生命、背包数量/容量；不将World对象或内部坐标传入Agent。Web可展示模拟器状态，明确为SIMULATOR_UI_ONLY，决策world_state为IMAGE_PIXELS_ONLY。

STATE增加QUALIFY：PREPARE → QUALIFY → ENTER → SEARCH → NAVIGATE/COMBAT/LOOT → VERIFY → SETTLEMENT。资格检查限定模拟角色存活、可见入口与有效背包；未在入口先寻路。每次重新观察选择目标、重算路径；目标迁移或新障碍后不继续旧路线。RECOVER用于重新采样、重选目标、拾取重试或实际模拟转存。不可恢复的运行在runs记录FAILED，Worker结束状态STOPPED表示线程释放，不代表任务成功。

agent_observation保存采样PNG、SHA-256、算法版本、像素感知和错误码。agent_decision保存run_id、stage_id、observation_id、前后图像关联、world_state、selected_goal、action_type、decision_reason、expected_result、actual_result、decision_latency（毫秒）、error_code、完整计划路线。AGENT_DECISION通过原SQLite日志和SSE实际发送；world_state仅从图像得到。图像角色缺失时记录UNKNOWN与VISION_FAILED，不执行动作。

## 独立模拟结算

research_settlement按run_id+stage_id记录。stage_id=0是全程；1–4是阶段小计。金币、碎片、材料与模拟补给成本从实际loot/deposit日志求和，并与环境累计资源比较。成功写入runs与独立结算在同一事务；不能重复结算。阶段时长来自enter/stage/exit事件时间，阶段成功来自清场事件；全程时长为真实墙钟时间，暂停也计入展示时长，活动超时排除暂停时间。

失败/主动停止也保留已拾取资源小计，success=false不计入成功收益。背包转存仅释放占用槽，累计资源保留，成本单位SIMULATED_SUPPLY_UNIT；不会换算人民币或声称现实收入。成功率分母为COMPLETED+FAILED，STOPPED单列，无样本返回NULL。意图注入的失败样本与正常通关样本在报告中分开。

原模拟器收益接口保留，九星页面顶部指标与独立报表仅显示九星结算。GUI实时画面叠加当前计划路线和人物；决策列表能展开原图；历史回放读取数据库保存的当次PNG，不用当前画面冒充历史。SSE批量更新，完整结构仅在展开后渲染，避免大决策日志拖慢控制。完整日志仍可导出。

## API

写请求保留本机/同源/X-Agent-Control校验。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/scenes | 原创与九星研究场景 |
| POST | /api/agent/start | rounds、seed、fault、scene_id（默认original或NineStarResearchDungeon） |
| POST | /api/agent/pause、resume、stop、emergency-stop | 原控制接口，作用于实际Worker |
| GET | /api/agent/status、/api/dungeon/status、/api/frame/latest | 当前场景、首领、角色、路线、真实PNG |
| GET | /api/research/decisions | run_id、limit，真实决策记录 |
| GET | /api/research/observations/{id}/frame | 对应历史采样PNG |
| GET | /api/research/runs/{run_id} | 固定孪生版本、配置快照与测试故障覆盖 |
| GET | /api/research/settlements | run_id可选，阶段和全程结算 |
| GET | /api/research/earnings | 独立模拟收益、成功率及样本量 |
| GET | /api/research/future-resource-records/schema | 人工审核资源/游戏内成交的预留字段 |
| POST | /api/research/future-resource-records | 预留接口，当前501，不写入真实成交/收益 |

未来资源记录要求GAME_OBSERVATION、MANUAL_REVIEW、reviewed_fact_ids、版本、时间、物品、数量、游戏内货币、证据ID；当前没有自动成交、价格预测或真实收入接口。

## 异常与停止条件

| 异常 | 实际处理 | 停止条件 |
|---|---|---|
| target_disappeared | 目标实际迁移，原攻击无效，重新识别与规划 | 无可行路径/重试耗尽FAILED |
| path_blocked / stuck | 下一格新增真实障碍或一次拒绝，下一图像重跑A* | 无可行路径/验证失败超过3次重试FAILED |
| character_dead | 实际反击使生命归零 | 立即FAILED，不伪造复活或成功结算 |
| vision_failed | 一次传感器黑帧，记录证据后重新采样 | 最多3次重试，持续失败FAILED |
| stage_timeout | 根据实际活动时间预算，暂停排除 | 单阶段60秒；测试覆盖0秒，FAILED |
| loot_failed | 拾取真实拒绝，背包不变，再次观察重试 | 最多3次重试，持续失败FAILED |
| bag_full | 像素HUD显示容量不足，执行模拟仓库转存，记录成本 | 转存验证失败超过3次重试FAILED |
| scene_load_failed | 创建运行记录后实际加载失败 | 立即FAILED，保留失败记录 |
| worker_interrupted | 异常捕获或真实进程终止后的重启识别 | 研究运行FAILED，不自动续写成功 |

额外vision_persistent、loot_persistent用于验证停止上限；首次失败+3次重试总共4次失败观察/动作。总活动180秒、1000步、单动作2秒为原有保护；不支持无限重试。故障覆盖写入该run配置快照并标记SIMULATED_ASSUMPTION。

## 数据迁移与回退

005_research新增research_run、agent_observation、agent_decision；006_research_settlement新增独立结算表。已有runs、logs、官网事实、V1.2观察与twin表没有重建或清空。SQLite迁移版本2、3、4、5、6。

停止服务后执行：

```powershell
.\.venv\Scripts\python.exe scripts/migrate_research.py --service-stopped --action upgrade
.\.venv\Scripts\python.exe scripts/migrate_research.py --service-stopped --action rollback
```

工具先一致性归档整个SQLite到reports/research-migration-时间/database.sqlite3；回退006再005，原历史与孪生记录保留。归档包含运行PNG。不要直接拿旧数据库覆盖当前库而丢失后来的日志。旧migrate_observation工具会阻止越过005/006回退；需先回退研究模块，再回退观察模块。回退后使用对应V1.2源代码，V1.3启动会重新幂等建表。
