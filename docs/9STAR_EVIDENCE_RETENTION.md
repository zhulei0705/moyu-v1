# 九星 V1.3.3 证据生命周期

本版本仅用于自建模拟器或明确授权的测试环境。所有核心动作前后画面、识别结果、完整决策、状态变化、阶段变化、击败、拾取、背包、结算、异常恢复和控制命令永久保留。收益、寻路、视觉识别和战斗算法没有修改。

## 三层数据

1. 核心证据仍使用原 SQLite 表和原 ID；所有重要决策字段完整可查。结算继续使用原事务及 `(run_id, stage_id)` 唯一约束，不重放结果未知动作。
2. 动作画面采用 PNG 无损压缩 level 9，以及 SHA-256 内容复用。观察记录仍各自独立，`evidence_frame_ref` 连接到 `evidence_blob`。旧记录保留内嵌 PNG，新接口优先读取内嵌数据，再解析哈希引用。每个唯一画面保留，故障前后的动作观察不采样、不删除。分阶段关键画面自然包含在完整观察链中，不另造假证据。
3. 普通诊断可调用 `Evidence.debug`，按级别过滤、100 行一批写 JSONL，默认 4 MiB 分片；WARN/ERROR立即刷盘。`capture_debug`仅用于额外诊断画面，默认 1 秒间隔，最多 12 帧的故障前环形缓存；异常时落盘缓存及当前画面。动作证据不经过这个队列。保留时间配置仅作计划，当前版本不会自动删除。

核心观察写入首先保存内嵌 PNG，再持久化哈希对象及引用，最后清空新记录的重复内嵌内容。中断发生在任何一步都有完整画面副本；可能留下重复副本，但不会留下指向不存在画面的核心观察。默认不转换或压缩现有历史记录。迁移 008 是增量表结构。

## 容量保护

默认硬阈值仍为 2 GiB，软阈值 80%，磁盘保留至少 64 MiB。主库物理文件、WAL、SHM、外部 `observation-media` 及该数据库的额外诊断目录纳入统计。每 5 秒刷新统计，按最近最多 120 个样本计算主库逻辑页与外部媒体的净增长率；WAL 纳入真实占用，但不重复当成长期增长。零/不足增长不虚构耗尽时间。

每次动作及每轮开始前检查容量；原逻辑页 2 GiB 检查仍保留。因检查间隔和正在提交的事务存在有限超调，保留的磁盘余量用于安全退出，不表示精确字节限流。核心事件不因软阈值过滤。软阈值或异常趋势使额外诊断截图间隔扩大 8 倍；核心动作截图继续全量保存。异常趋势依据至少 12 个样本，瞬时速率超过窗口均值 3 倍且超过 1 MiB/s。

`/api/storage/status`及`/api/agent/status.storage`提供真实占用、增长、剩余磁盘、预测、告警和最近归档/停止原因。数据库状态 `CONNECTED` 表示真实连接查询成功，不等同于完整性检查；完整性验收独立使用 `PRAGMA integrity_check`。写入失败使 Worker 失败并停止后续动作；持久化失败时需要人工审核，不生成成功结算。

## 配置

数据库旁的 `<database>.retention.json` 可指定以下字段，启动时读取；不提供文件则使用默认值。

```json
{
  "hard_limit_bytes": 2147483648,
  "soft_ratio": 0.8,
  "disk_reserve_bytes": 67108864,
  "debug_level": "INFO",
  "debug_batch_size": 100,
  "debug_shard_bytes": 4194304,
  "debug_capture_interval_seconds": 1,
  "debug_retention_days": null,
  "archive_retention_days": null,
  "delete_enabled": false
}
```

禁止关闭保护：硬限额不得低于 64 MiB；磁盘保留不得低于 64 MiB；软比例必须在 0.5–0.95；`delete_enabled=true`会拒绝启动。生产限额调整及升级另行审批，默认限额未提高。

## 归档、备份和清理

`Evidence.archive(new_path)` 使用 SQLite 在线 backup 创建全新副本，执行完整性检查，写字节数与 SHA-256 清单；目标存在时拒绝覆盖。归档结果和失败告警可监控。原库不删除。此接口归档数据库（含全部核心 PNG BLOB）；外部导入视频、预览和额外诊断文件必须另行按清单备份，数据库归档不是整个目录的完整归档。

当前版本不提供实际清理入口。清理前必须：形成文件/记录清单；取得单独授权的保留策略；完成数据库及所有外部媒体备份；验证哈希与完整性；验证所有帧、决策、媒体引用；确认可回滚；最后才执行经授权清理。普通调试可以压缩归档；完整决策的日志副本可在未来按引用方式优化，但本轮保持完整字段以兼容历史回放。

## 降级

完整数据库、导入视频/预览及诊断目录可使用 `scripts/archive_evidence.py --db <隔离数据库> --destination <新zip路径>` 生成压缩归档。先创建一致性SQLite副本，复制媒体，记录逐文件SHA-256，再验证ZIP CRC及所有内容哈希。保留原件和工作快照，不删除源文件，也不覆盖现有归档。成功结果写入数据库旁监控元数据，由运行控制台下一次采样读取。恢复时按清单的source/path映射还原，或在隔离恢复库中改写外部媒体路径并验证；不能仅提取数据库后删除源媒体。

使用这个完整归档流程时，峰值磁盘应预留工作证据、原始快照和ZIP三份的最坏情况空间；不可假定视频一定有明显压缩率。

停止并备份隔离实例后，执行 `backend/migrations/008_evidence_down.sql`：先拒绝缺失帧引用，再恢复新观察的内嵌 PNG，随后删除新增的复用表及迁移记录。必须检查每帧 SHA-256、SQLite 完整性、决策引用和结算一致性，才能使用旧源码。不得仅将旧源码指向含空内嵌 PNG 的新库。生产首选恢复成套经验证的源码与数据库备份，保留升级后数据供审计。
