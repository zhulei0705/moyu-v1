# V1.2 场景观察与九星研究

入口 http://127.0.0.1:8000/#/observations。运行控制台、官网知识库、原模拟器保持独立。

## 页面

- `/#/observations`：观察中心，实际计数与授权导入。
- `/#/media`：PNG/JPG/MP4/WebM 管理、原图下载、SHA-256、间隔抽帧。
- `/#/analysis`：全图或指定区域 OCR、坐标文本、名称与任务/背包文字、模拟像素检测。
- `/#/annotations`：拖框、JSON 编辑、撤销、历史版本；三类坐标明确区分。
- `/#/boss-samples`：BOSS 名称样本；无识别结果时保持 UNKNOWN。
- `/#/review`：待审核、UNKNOWN、拒绝/已确认、人工纠正与官网差异。
- `/#/twins`：独立九星研究配置与历史版本、证据列表。
- `/#/evidence`：观察、原始媒体、算法、区域、审核记录。

图片最大20MB/1600万像素，视频最大100MB/10分钟；每视频最多60帧/100MB抽帧，间隔0.5至600秒。服务校验扩展名、签名与实际解码，受管文件使用SHA路径，原文件名不用于存储路径。未知版本、采集时间、服务器保持NULL。视频帧关联父视频与秒偏移，采集时间保持原视频提供的时间，不擅自推断帧时间。

OCR使用本地RapidOCR/ONNX CPU。全图词典匹配仅产生候选观察；可指定MAP_NAME、MONSTER_NAME、BOSS_NAME等文字区域。没有官服人物图像模板时角色检测保持UNKNOWN。模拟器颜色分割只读导入的图像像素，不读取World内部坐标。识别置信度不是准确率。当前不提供官服通用物体识别模型。

人工审核只产生VISIBLE_IN_FRAME_ONLY事实；模拟器样本始终SIMULATED_ASSUMPTION。官网历史事实保持原表与原版本。当前自动差异匹配仅对九星副本级同字段进行提示，不是跨版本有效性判断，也不推断掉落率或技能规则。

## API

所有写入POST继续要求 `X-Agent-Control: local-console`、本机与同源校验。

| 方法 | 路径（前缀 /api/observations） | 用途 |
|---|---|---|
| GET | /status | 实际资料、观察、审核、UNKNOWN计数 |
| GET/POST | /media | 列表/授权multipart导入，metadata为JSON |
| GET | /media/{id} | 元数据、观察、抽帧、标注版本 |
| GET | /media/{id}/preview、/file | 安全预览、原文件下载 |
| POST | /media/{id}/extract | interval_seconds、max_frames |
| POST | /media/{id}/analyze | regions可选，每项kind与region=[x,y,w,h] |
| GET | /results | status、kind筛选 |
| GET | /results/{id} | 原图证据与人工审核 |
| POST | /results/{id}/review | confirm/correct/reject、reviewer、rationale、field、corrected_value |
| GET | /facts、/conflicts | 已审核事实/保留双方证据的差异 |
| POST | /media/{id}/annotations | annotations、author、reason、base_revision |
| GET/POST | /twins | 历史版本列表/保存新版本 |
| GET | /twins/evidence | 现存可引用证据，排除官网UNKNOWN |
| GET | /twins/{scene_id} | 指定场景版本历史 |

原 `/api/logs` 增加 `tail=true`：返回最近limit条，仍按ID升序；默认分页行为不变。控制台首次加载最近500条，完整历史通过原查询、任务回放与导出读取。SSE保留Last-Event-ID与after。

## 场景结构与边界

配置包括scene_id、dungeon_id=alama、game_version、evidence_ids、map_regions、navigation_nodes、obstacles、enemy_definitions、stage_triggers、visible_mechanics、reward_definitions、confidence、validation_status。附加base_revision、author、reason用于提交。

每条记录必须声明OFFICIAL_FACT、OBSERVED_FACT或SIMULATED_ASSUMPTION。真实证据条目格式 `{data_class,evidence_ids:[单个证据ID],value:证据原值,label:可选}`，不允许加入无证据的机制字段；游戏版本必须一致。地图/游戏坐标的依据在人工标注中保存，引用时保留原结构。测试假设须有assumption_note与execution_environment=SIMULATOR，不得引用真实事实冒充假设来源。DRAFT允许空草稿；EVIDENCE_LINKED须实际引用全部声明证据，仅说明引用校验通过。全部配置为RESEARCH_ONLY，current_game_verified=false、VISIBLE_PORTION_ONLY，不连接原Agent或官服执行。

## 迁移与回退

003_observation创建媒体、观察、审核、事实、冲突、标注、事件表；004_twin仅新增场景版本表。schema_migration记录3/4；新增表不修改旧表。执行前停止服务：

```powershell
.\.venv\Scripts\python.exe scripts/migrate_observation.py --service-stopped --action upgrade
.\.venv\Scripts\python.exe scripts/migrate_observation.py --service-stopped --action rollback-twin
# 回退整个观察模块（同时回退004）：
.\.venv\Scripts\python.exe scripts/migrate_observation.py --service-stopped --action rollback-observation
```

回退自动将整个SQLite归档到reports/migration-时间/database.sqlite3，媒体文件保留原位；删除的是新增模块表，原runs/logs/官网资料不删除。回退后使用相应旧源代码，当前源代码启动会幂等重新建新表。恢复新增记录应使用归档，不要将旧备份覆盖当前库而丢失后来运行日志。开发前完整快照在reports/v12-current-audit。

## 验证与后续

pytest、前端构建、原浏览器/API验收与新观察浏览器验收均使用隔离库。`scripts/observation_browser_test.py --url ...`会在目标库真实导入原创模拟图并产生审核/标注/场景记录，因此只在隔离测试服务执行。`test.ps1`提供统一回归入口。

需用户提供授权官服截图/录像后才能评估实际画面OCR与物体识别准确性。当前真实官服BOSS属性、路径连通、阶段触发、障碍碰撞、奖励概率和技能机制仍未验证。下一步先按版本采集与审核多个画面，再建立坐标标定、标注基准集和同版本证据关联；任何新增机制仍以证据为准。
